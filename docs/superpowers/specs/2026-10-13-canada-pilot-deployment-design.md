## Pages routing and indexing

Recommend a public pilot excluded from search indexing initially. The country page retains its `noindex,nofollow` metadata. The deployment package adds a reviewed `_headers` rule applying `X-Robots-Tag: noindex, nofollow` to `/*`, covering the remaining pilot pages too. This is a crawler directive, not privacy or authentication. Everyone with a production or deployment URL can access the intended research; provider preview URLs are public by default. A later indexing decision is separate. [Pages headers](https://developers.cloudflare.com/pages/configuration/headers/), [preview access and indexing](https://developers.cloudflare.com/pages/configuration/preview-deployments/).

Include a top-level `404.html` with a plain **Page not found** message and a homepage link. It contains no observation data, private identifiers or client island. Without this file, [Pages assumes a single-page application](https://developers.cloudflare.com/pages/configuration/serving-pages/) and serves the homepage at otherwise missing paths. Both private preview routes and missing country/product/data paths must actually return HTTP 404 at the deployed site. Keep default Pages caching; add no Functions, `_worker.js`, redirects, analytics, bindings or cache override.

Author these two small deployment files outside ordinary Astro public assets, proposed under `deployment/pages/`. Add them only to the explicitly prepared publication directory. Normal, preparation and fixture builds therefore keep their existing routes/output. `_headers` is a provider-consumed control file, not a served asset; verify its live effect instead of expecting a downloadable byte copy.

## Rollback and first-deployment withdrawal

For subsequent releases, preserve the last approved static artifact and its successfully deployed production ID. [Pages rollback](https://developers.cloudflare.com/pages/configuration/rollbacks/) can return the canonical project to a successful production deployment; previews are not rollback targets. Rollback changes the hosted artifact, not country/product pointers, local archives or the release-acceptance record. Verify the resulting canonical site and preserve its receipt.

A first deployment has no earlier production artifact. Prepare a separate tiny withdrawal package before upload: `index.html` and `404.html` say **Pilot temporarily unavailable**, expose no research data, and carry the same noindex control. Its exact files/ZIP receive their own readback identities. The final deployment decision should include permission for this reversible replacement on the new trade project if live checks fail. If authorized and needed, upload it to the same target, verify the canonical research paths cease serving the pilot, and record `canonical-withdrawn`; do not label this a rollback to a nonexistent prior site.

Replacing the canonical deployment does **not** remove older hash-based deployment URLs. [Pages preview URL behavior](https://developers.cloudflare.com/pages/configuration/preview-deployments/) documents that earlier deployment addresses remain accessible, and the latest deployment for a branch cannot simply be deleted. Inventory all URLs recorded during the operation and check their serving state. A withdrawal record must state which URLs still expose the pilot. To remove the first pilot's project and deployments from Cloudflare, the available [project deletion operation](https://developers.cloudflare.com/api/resources/pages/subresources/projects/methods/delete/) is permanent and requires separate explicit confirmation at action time. Never delete the unrelated Worker, R2 bucket or any local proof. A complete provider withdrawal is not established until the previously recorded URLs no longer serve the pilot; it cannot retract copies already downloaded by visitors.

If upload or live validation fails, retain the package/evidence, report the provider outcome and carry out only the pre-authorized reversible withdrawal or a confirmed permanent action. If neither is authorized, report the outstanding exposure and ask for the exact needed action. No undocumented automatic deletion, pointer rewind, paid rescue or source refresh follows a hosting failure.
