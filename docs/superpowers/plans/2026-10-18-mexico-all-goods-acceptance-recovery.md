## Intended outcome and boundary

The owner wants the next Mexico development milestone completed without reopening product comparisons or creating routine permission pauses. The completed research supports all-goods totals for September 2024–August 2026; it does not support ordinary-product continuity. Success is a usable, recoverable candidate, an honest eligibility result, preserved evidence and actual cleanup.

This milestone implements **candidate acceptance criteria and recovery**, not installation of an accepted country release. Its lifecycle is:

`prepared → recovered/independently checked → implementation review and exact-head CI → eligible candidate`

Even an eligible candidate keeps `releaseAccepted:false`, `classificationAccepted:false`, `publicMexicoProfile:false` and `productComparisons.available:false`. There is no real selector, current pointer, accepted-state restoration or website consumer in this milestone. The later canonical-install decision must name the actual candidate/report digests and a durable preservation arrangement. A recovery package is not a backup of the original national trade bodies.

Recommended approach: an additive Mexico-only contract. Direct reuse of Canada's policy would import its fixed 1220 identity, 223,049-row assessment, 17 compatible comparisons and 41/7 reference exception. A generic multi-country refactor would broaden an accepted production path before it is necessary. Keep Canada unchanged, reuse neutral path checking where appropriate, and add only the offline Mexico components required here.
