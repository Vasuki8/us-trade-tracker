**Goal:** Establish the missing sixteen real-data Firefox journeys on Linux against the exact previously published pilot, without changing the website or claiming that Windows Firefox works.

**Architecture:** Adapt the proven retained-profile harness into narrow tracked verification tooling. A small reviewed public expectation record binds existing served-file and CSV identities; a manually dispatched Linux job checks only the fixed historical deployment. Reuse the existing bounded HTTP primitive without weakening the ZIP-gated `site:verify` command. This is verification, not a new release or download-staging system.

**Tech Stack:** Existing Node 24, locked Playwright 1.64.0, TypeScript/Vitest, Python package verifier and standard GitHub Actions Ubuntu runner. Existing pinned actions only; no dependency, service or browser-version upgrade.

**Spec:** This combined bounded design and the research/download/validation requirements in `docs/superpowers/specs/2026-10-08-us-trade-tracker-design.md`; current browser evidence in `docs/validation/browser-compatibility-checkpoint.md`. ## Assessment and recommendation

PR118 is merged on clean main `9f04964de19175d45ccff6d80a6a12f10da34e59`. Both final-head CI runs passed the original 200 browser cases and 48 Firefox/WebKit fixture cases without browser skips/retries. Actual archive/cache cleanup is complete. WebKit passed sixteen retained-site journeys locally; Windows Firefox failed before page creation and its sixteen retained journeys remain unexecuted. These are different evidence classes.

Recommend one narrow Linux Firefox checkpoint, then hold feature expansion for owner task observations or a separately authorized real release. The existing owner-run study kit already exists; another preparation framework is unnecessary. The [Census FT900 calendar](https://www.census.gov/foreign-trade/schedule.html), rechecked October 16, schedules September 2026 for November 4, 2026 at 8:30 a.m. Eastern. A calendar entry establishes neither source availability nor accepted new website data. This plan adds no later wake-up, polling or scheduled work.

Alternatives considered: repairing Windows/browser binaries would address the host rather than the website and has no established safe diagnosis; leaving all real-data Firefox evidence open avoids work but misses a concrete verification gap. A generalized remote package/release subsystem would be disproportionate. The [Playwright CI guidance](https://playwright.dev/docs/ci-intro) supports running the pinned engine on an existing Linux Actions runner; this does not certify stock Firefox, Safari, real devices, screen readers or participant usability.
